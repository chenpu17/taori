# 01 · 产品定位

## 品牌

| | |
|---|---|
| 名称 | **Taori** |
| 读音 | /taːori/（"塔奥里"，三音节均匀） |
| 含义 | 来源于"weave"（织）的意象——把多个 AI 模型像丝线一样编织成一条不断的工作流 |
| 英文 slogan | *Taori weaves many models into one continuous flow.* |
| 中文 slogan | 把多个模型，织成一条不断的工作流 |
| 视觉锚点 | 经纬交织 / 多线汇聚（logo 方向） |

"编织"是产品三主线的统一隐喻：
- **失败兜底** = 一根线断了，换另一根继续织
- **成本透明** = 每根线都看得见
- **多模型圆桌** = 多色丝线交织成图案

中文文案中**直接保留 "Taori"**，不强行翻译成"多织"等中文译名。

## 一句话定位

> 一个"多模型工作编排助手"。用户不必理解每个模型的差异，只需表达目标；系统负责协调合适的模型、在失败时换路、在多模型分歧时帮助用户决策。

## 核心叙事（三条产品主线）

> **"让 AI 工作不再断流，每一分钱都看得见。"**

1. **失败兜底**（最高频）—— 模型挂了、慢了、限流了、效果差了，助手帮你换路继续干。详见 [04-failure-resilience.md](./04-failure-resilience.md)
2. **成本透明**（最高频）—— 调用前预估、调用中实时、调用后聚合，BYOK 用户的"安全感"。详见 [03-cost-transparency.md](./03-cost-transparency.md)
3. **多模型圆桌**（标志性）—— 重要决策时，多个模型帮你形成共识/分歧/决策。详见 [05-roundtable.md](./05-roundtable.md)

## 与普通 ChatGPT 类产品的区别

- 不是单模型对话窗口，而是一个**可以管理"模型能力池"**的工作台
- 核心价值不是"接入很多模型"，而是让用户在真实工作中**更顺畅地选择、调用、比较、切换、记忆和组合**不同模型能力
- 把"模型"从配置项升级为"协作伙伴"

## 目标用户与形态

| 维度 | 决策 |
|---|---|
| 目标用户 | **多模型重度用户**：已经同时使用多个 AI 模型、愿意自带 Key、经常切模型、对成本/质量/稳定性敏感 |
| 商业模式 | 本地工具，用户自带 Key（BYOK），支持 OpenRouter 等聚合平台一键接入 |
| 平台形态 | 桌面端优先（便于操作本地文件、隐私友好、自带 Key 体验最佳） |

## 核心产品对象

### 1. 模型（Model）

按能力类型分类：聊天/推理、图像生成、图像理解（视觉）、视频生成、ASR、TTS、Embedding、代码模型、OCR/文档解析、多模态理解。

### 2. 能力（Capability）

面向用户表达"我要做什么"，与模型解耦：写作 / 推理 / 搜索 / 画图 / 生成视频 / 读图 / 读文件 / 生成代码 / 会议总结 / 翻译 / 多模型辩论 …

### 3. 记忆（Memory）

**用户视角三级**（UI 暴露），简化心智：

| 层级 | 适用场景 |
|---|---|
| 仅本次 | 一次性任务 |
| 当前会话 | 当前对话/项目期间生效 |
| 以后默认 | 长期偏好 |

> 内部实现可保留更细粒度（如任务级），但不暴露给用户。

### 4. 工作流（Workflow）

通用执行链路：

```
用户表达目标 → 系统识别需要的能力 → 选择/推荐模型 →
执行 → 失败时降级或换模型 → 结果汇总 → 询问是否保存偏好
```

## 设计原则

1. **用户始终知道现在在用哪个模型、花多少钱** —— 杜绝黑盒
2. **失败 = 决策机会，不是错误提示** —— 永远给出下一步建议
3. **成本可见，每一分钱都看得见** —— 安全感来自透明
4. **记忆必须可控** —— 每次记住都明确询问，每个偏好都可查可改
5. **多模型协作 ≠ 多模型并发** —— 强调"协作出比单模型更好的结果"
6. **桌面端优先体验** —— 利用本地能力做云端做不到的事
7. **不让用户做太多配置** —— 圆桌角色自动生成，新手立即可用
