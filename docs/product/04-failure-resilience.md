# 04 · 失败兜底专题（产品主线）⭐

## 设计哲学

> **失败 = 决策机会，不是错误提示。**
> 用户每天都会遇到模型慢、报错、限流、效果差。这是高频痛点，也是本产品最具差异化的体验。

错误提示必须是**决策型**而非报错型：

> 模型 A 当前不可用（额度不足 / 网络异常 / 内容审核拒绝）。
> 是否改用模型 B？预计质量相近，但风格控制稍弱。

## 用户可选动作

- 换用推荐模型
- 手动选择其他模型
- 稍后重试
- 修改提示词后重试
- 查看失败原因详情

## 失败规则精细化

| 触发条件 | 系统行为 |
|---|---|
| 单次失败 | 弹决策提示让用户选（不静默处理） |
| 24h 内同模型连续/累计失败 ≥ 3 次 | 临时**降权**（在选择器中下移，标灰提示），但仍可手动选用 |
| 24h 内累计失败 ≥ 5 次 | 临时**禁用 24h**（自动跳过它做兜底候选） |
| 内容审核（content_filter）失败 | **不计入失败次数**，因为可能是 prompt 问题，不是模型问题 |
| 用户手动重试该模型成功 | **立即清除异常标记** |
| 提供"自动降级"开关 | 失败后按预设顺序自动尝试，全失败才提示（默认关闭） |

> **核心原则：系统不擅自把模型拉黑，所有降权/禁用都对用户透明可见、可手动恢复。**

## 错误分类

错误分类直接决定提示文案，避免笼统的"失败了"：

| 分类 | 文案示例 | 是否计入失败 |
|---|---|---|
| `quota` | 额度不足 / 余额耗尽 | ✅ |
| `network` | 网络异常 / 超时 | ✅ |
| `rate_limit` | 触发速率限制 | ✅ |
| `content_filter` | 内容审核拒绝 | ❌ |
| `unknown` | 未知错误（附带原始信息） | ✅ |

## 自动降级（可选开关）

- 默认**关闭**——失败时弹决策提示
- 用户可在偏好中开启"自动降级"——失败后按 `fallback_order` 自动尝试下一个模型
- 自动降级生效时仍要**显式告知用户**已切换：
  > 已从模型 A 切换到模型 B，原因是 A 超时。结果风格可能略有差异。

## UI 表现

### 降权状态在选择器中
```
○ GPT-4o          💰💰💰  ~$0.005/次
○ Claude          💰💰    ~$0.003/次   ⚠️ 24h 内 3 次失败
●(灰) GPT-4-old   💰      ~$0.001/次   🚫 临时禁用至 18:42
○ Haiku           💰      ~$0.0003/次  ← 推荐
```

用户仍可点击降权/禁用模型，只是默认不会被自动选中。

### 健康状态面板（第二阶段）
单独一栏看每个模型的最近 24h 成功率、平均耗时、最近一次错误，便于排查。

## 实现要点

详细伪代码与状态机见 [架构文档 04-data-and-storage.md](../architecture/04-data-and-storage.md#失败兜底实现要点)。

关键实现点：
- 失败计数滚动窗口（24h），按 `model_id` 维度
- 异常状态字段：`failure_count_24h` / `demoted` / `disabled_until`
- 成功调用立即清除异常标记
- 错误分类器：把各 provider 的原始 error 映射到统一分类
