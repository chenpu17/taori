# 05 · 多模型圆桌（标志性功能）

> 命名候选：多模型圆桌 / AI 专家会议 / 模型评审会 / Consensus Mode

## 核心设计原则

1. **用户只抛话题，不做配置** —— 模型组合与角色视角由系统自动安排
2. **不是让模型聊天，是帮用户做决策** —— 输出结构化结论
3. **两种模式，避免炫技** —— 简单问题用快速模式，重要决策用深度模式

## 两种默认模式

| 模式 | 流程 | 适用 |
|---|---|---|
| ⚡ 快速模式（默认） | 一轮独立观点 + 自动总结 | 日常多视角参考 |
| 🔍 深度模式 | 盲审 → 互见反驳 → 总结 | 重要决策 |

启动圆桌时让用户选模式（默认快速），并显示**预估调用次数与成本区间**。

## 界面形态（纵向多列）

```
┌──────────────────────────────────────────────┐
│ 话题：如何设计一个面向设计师的 AI 助手？        │
│ 模式：🔍 深度  · 预计 7 次调用 · ~$0.08–0.15   │
│ （系统已自动安排 3 位"专家"：战略 / 用户 / 技术）│
├────────────┬────────────┬───────────────────┤
│  GPT-4o    │  Claude    │  Gemini           │
│  战略视角   │  用户视角   │  技术视角          │
├────────────┼────────────┼───────────────────┤
│  第1轮观点  │  第1轮观点  │  第1轮观点        │
├────────────┼────────────┼───────────────────┤
│  第2轮观点  │  第2轮观点  │  第2轮观点        │
└────────────┴────────────┴───────────────────┘
   [👁 已开互见] [📝 总结结束] [➕ 再来一轮]
```

## 结构化输出（圆桌总结的固定模板）

```
─────── 圆桌结论 ───────
✅ 共识：所有模型都同意的要点
⚠️ 分歧：观点不一致的地方（标明各方立场）
🚨 风险：被识别出的潜在问题
🎯 推荐决策：综合建议
📋 下一步行动：具体可执行的步骤
─────────────────────
本次圆桌成本：$0.124（明细见展开）
```

## 用户可控选项（最小集）

- 再来一轮 / 总结结束
- 切换模式（快速 ↔ 深度）
- （高级）手动调整参与模型、视角

## 附加机制

- 支持导出 Markdown 报告
- 支持自动提取"分歧点"
- 圆桌总结附带成本明细（产品主线之一：成本透明）

## 自动角色生成机制

> 详细的元 Prompt 模板见 [架构文档 04-data-and-storage.md](../architecture/04-data-and-storage.md#圆桌自动角色生成元-prompt)。

两阶段实现：

1. **阶段 A：话题分析**（用便宜模型如 Haiku / GPT-4o-mini 调度）
   - 分析话题类型（business / technical / creative / decision / research）
   - 推荐参与模型数量（通常 3）
   - 为每个参与模型分配**差异化视角**（至少一个"风险/反对"视角）
   - 推荐总结模型

2. **阶段 B：每轮发言**
   - 注入 persona_prompt 作为 system message
   - 第二轮时把第一轮的其他观点拼入 prompt
   - 控制每位发言 300 字以内

3. **阶段 C：总结**
   - 严格 JSON 输出（共识 / 分歧 / 风险 / 决策 / 下一步）

**降级策略：** 角色生成失败 → 退回固定 3 角色（综合 / 批判 / 实践）

## 为什么要两阶段

- 让"谁参与、什么角色"成为一次显式 LLM 调用，可观测、可审计、可缓存
- 用便宜模型做调度，贵模型只用在内容生成 → 成本可控
