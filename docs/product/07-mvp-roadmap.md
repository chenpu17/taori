# 07 · MVP 路线图

> **承认事实：** 把所有功能塞到一个"MVP"里已不再准确。圆桌是**标志性功能**但不是最早验证的功能。
> 第一个要验证的产品价值闭环是：**OpenRouter 配置 → 聊天 → 显示成本 →（M2 接力）失败时推荐换模型 → 用户能继续完成任务。**
> M1 内测版只交付前三段（配置 + 聊天 + 成本透明 L1/L2 + 错误分类文案 + 重试）；**"决策型推荐换模型"是 M2 的核心交付**。两版合在一起才是完整价值闭环。

## M0 — 骨架（地基）

> 不直接面向用户，但是后续所有版本的前提。

- pnpm workspace 搭建
- Tauri + React + Sidecar 三方互通（hello world 级 SSE 跑通）
- SQLite + Drizzle 迁移机制
- OS Keychain 存取 API Key

## M1 — 内测版（验证基础闭环）

**一句话：** 配好模型就能稳定聊天，看得见花了多少钱。

- ✅ 模型配置中心（轻量版）+ OpenRouter 一键导入
- ✅ 单模型聊天（流式）
- ✅ 成本透明 L1+L2（实际成本展示 + 价位徽章 + 发送前预估）
- ✅ 文件拖入聊天（图片优先）
- ✅ OS Keychain 存 API Key

## M2 — 核心 MVP（验证产品主线）

**一句话：** 模型挂了/不合适时不卡住，跨能力调用顺畅，成本始终在视野里。

- ✅ 失败兜底（决策型提示 + 渐进式降权 + 错误分类）
- ✅ 聊天中跨模型调用（图像生成弹窗 + 三级记忆）
- ✅ 成本透明 L3+L4（轻量实时显示 + 高成本前置确认 + 会话仪表盘）
- ✅ Capability Bus + 内置工具（image_generate / file_read）；详见 [09 · Agent 与工具体系](./09-agent-and-tools.md)

## M3 — 标志性版本（差异化亮点）

**一句话：** 重要决策时，多个模型帮你形成结构化结论；可接入用户自有工具。

- ✅ 多模型圆桌（快速/深度双模式）
- ✅ 自动角色生成（元 Prompt）
- ✅ 结构化总结输出（共识/分歧/风险/决策/下一步）
- ✅ Markdown 导出
- ✅ MCP 桥（本地 stdio）+ 工具中心 UI；详见 [09 · Agent 与工具体系](./09-agent-and-tools.md)

## 不在前三版（移到 v2）

完整能力卡 / 配置模板市场 / 健康面板 / 智能路由 / Pipeline / 知识库 RAG / 偏好学习 / 本地模型 Ollama / 视频音频模型 / 预算控制 / 全局快捷键 / 编辑器集成 / 智能省钱提示

## 实施优先级建议

按"风险优先 + 价值优先"开发：

| 顺序 | 模块 | 备注 |
|---|---|---|
| 1 | M0 骨架 | 三进程互通是所有后续的前提 |
| 2 | M1 配置 + 聊天 + 成本 L1/L2 | 第一个可演示的闭环 |
| 3 | M2 失败兜底 + 跨模型 + 成本 L3/L4 | 产品主线落地 |
| 4 | M3 圆桌 | 标志性功能，需要前三个稳定后再做 |
