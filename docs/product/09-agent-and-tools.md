# 09 · Agent 内核与工具体系（产品视角）

> **总原则：** Taori 不做"通用 Agent 框架"，做**多模型工作连续性驱动的工具编排**。  
> Agent 能力是手段，不是产品主线。MVP 阶段（M1/M2）不暴露 Agent 概念给用户。

## 1. 产品定位

| 我们做 | 我们不做 |
|---|---|
| 把"工具"作为模型能力的延伸（让模型能画图、读文件、查网页） | 通用 AutoGPT / 任务自治 Agent |
| 用户配好工具就能用，不写流程图、不写 prompt 模板 | LangGraph / CrewAI 风格的可视化编排 |
| 圆桌就是 Taori 的"原生多模型 Agent" | 让用户造自己的 Agent（v2 再考虑） |
| 支持本地 MCP Server 接入（标准协议） | 远程 MCP（M3 不做，v2 评估） |

## 2. 用户视角的三类"工具"

### 2.1 内置工具（Builtin）
Taori 自带、零配置：
- **图像生成** —— 聊天中说"画一张..."→ 弹模型选择 → 生成
- **文件读取** —— 拖入 PDF/图片/文本 → 自动抽取上下文
- **网页抓取** —— 粘贴 URL → 自动获取页面内容（M3 起）
- **剪贴板增强** —— 全局快捷键直送当前模型（M2 桌面能力的一部分）
- **代码执行（沙箱）** —— v2 评估，本地 sandbox 风险高

### 2.2 MCP 工具（用户接入）
用户在 **工具中心** 配置一个 MCP Server（参考 [Model Context Protocol](https://modelcontextprotocol.io)）：
- **来源：** 本地命令（stdio）/ 本地 HTTP（M3 起）
- **配置项：** 名称、启动命令/URL、启用开关、所属能力分类
- **自动发现：** Taori 启动 MCP server 后，自动列出它声明的 tools，并按 `capability` 注册到工具池
- **使用方式：** 用户**不需要手动调用**——支持 tool 的模型在聊天中会自动看到这些工具，按需调用

### 2.3 圆桌"原生 Agent"（M3 标志性能力）
圆桌不是普通工具，而是 Taori 自研的**多模型协作 Agent**：
- 用户抛话题 → 系统自动选择参与模型 + 角色 → 多轮发表观点 → 总结
- 内部会调用普通工具（如让某个模型边查网页边发言），但用户感知是"一个圆桌任务"，不是"一串工具调用"

## 3. 用户故事

| ID | 作为...我希望...以便... |
|---|---|
| AG-1 | 在聊天中说"画一张猫"，系统弹出可用图像模型让我选择，记忆我的偏好 |
| AG-2 | 添加一个本地 MCP Server（如 GitHub MCP / Notion MCP），无需重启 Taori 即可让模型调用 |
| AG-3 | 看到每个工具调用的成本，与 LLM 调用并列在会话累计中 |
| AG-4 | 工具调用失败时（MCP server 崩溃/超时），收到与模型失败相同体验的"重试 / 切换 / 跳过"提示 |
| AG-5 | 在工具中心查看所有已注册的工具及其健康状态，可临时禁用某个工具 |

## 4. 与产品三主线的关系

| 主线 | Agent/工具如何强化 |
|---|---|
| **失败兜底** | 工具失败用同一套 `classifyProviderError` 体系；MCP server 崩溃 → 提示重试/切换工具/跳过 |
| **成本透明** | 每次 tool_call 独立成本记录；会话累计含工具开销；用户始终知道"这次任务烧了多少" |
| **多模型圆桌** | 圆桌就是 Taori 的原生 Agent，借助工具池让多模型协作更深入 |

## 5. 路线图

| 版本 | 用户可见增量 |
|---|---|
| **M1** | **不引入** Agent / 工具概念。聊天 + 文件附件即止 |
| **M2** | Capability Bus 上线（用户无感）；内置 1–2 工具（图像生成、文件读取）；聊天中可触发跨模型工具调用 |
| **M3** | 工具中心 UI；MCP 桥（本地 stdio）；圆桌（自研多模型 Agent） |
| **v2** | 远程 MCP（带签名校验）；自定义工具脚本（用户写 JS/Python 沙箱）；Agent 模板市场 |

## 6. 范围明确

**明确不做（至少 M3 之前）：**
- 让用户编辑 Agent 流程图 / DAG
- 通用 AutoGPT 式自治循环（Agent 长时间无人值守跑任务）
- 远程 MCP server（数据/Key 外泄风险）
- 工具市场 / 商店（v2 评估）
- 多 Agent 系统（圆桌已经满足典型多模型协作需求）
