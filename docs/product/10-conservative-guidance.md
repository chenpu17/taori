# 10 · 保守引导与可解释工具执行

## 1. 背景

Taori 面向多模型重度用户。用户长期使用后会形成自己的模型偏好，因此现阶段不做自动模型动态路由，不替用户抢方向盘。

本阶段目标是提升顺滑度与信任感：

- 明确提示能力不匹配，但不自动切模型
- 工具执行过程可见，降低黑盒感
- 提供工作流模板，帮助用户组织任务，但模型仍由用户选择
- 继续复用现有记忆体系保存显式偏好

## 2. 产品原则

1. **建议，不接管**：系统只给出能力建议，用户点击后才切换模型。
2. **能力先于模型**：提示围绕“读图 / 工具 / 图片生成 / 成本”，不评价具体模型好坏。
3. **过程可解释**：工具调用要显示步骤、输入摘要、完成状态、耗时和结果摘要。
4. **模板不绑定模型**：工作流模板只填充任务结构，不改当前模型。

## 3. 首版范围

### 3.1 能力提示增强

触发条件：

- 输入包含搜索、抓取、URL 等意图，当前模型不支持 tools，但存在可用工具模型
- 输入带图片，当前模型不支持 vision，但存在可用视觉模型
- 输入疑似图片生成，但 `builtin.image_generate` 被关闭

交互：

- 在能力预检栏显示建议
- 提供“切换”或“检查工具”按钮
- 不自动切换当前模型

### 3.2 工具执行时间线

聊天模型调用内置工具时，助手消息内显示：

```text
工具执行
  搜索网页 · 完成 · 28ms
  输入：Taori multi model assistant
  结果：返回 2 条结果
```

首版覆盖：

- `builtin.web_search`
- `builtin.web_fetch`
- `builtin.image_generate`

### 3.3 内置工作流模板

模板入口复用聊天头部的模板选择器。新增内置工作流：

- 网页调研报告
- 图片生成并复核
- 决策简报

模板支持变量填写，但不绑定模型、不调用工具、不创建自动流程。

## 4. 特性到模块映射

| 特性 | `apps/web` | `apps/sidecar` | `packages/shared` | 数据 |
|---|---|---|---|---|
| 能力提示增强 | 能力预检栏新增建议与手动切换按钮 | 无 | 无 | 无 |
| 工具执行时间线 | 解析并渲染 `tool_trace` annotation | 工具执行前后写入 `tool_trace` annotation | 暂不新增类型导出 | 无 |
| 内置工作流模板 | 模板选择器内置工作流分组 | 无 | 无 | 无 |
| 用户偏好记忆 | 继续复用现有模型选择 / image model / persona / cost confirm 记忆 | 继续复用 `/v1/memories` | 无 | 无新表 |

## 5. 非目标

- 不做自动模型动态路由
- 不做 LLM Router
- 不自动调用圆桌
- 不让模板直接执行多步骤 Agent 流程
- 不引入工作流 DAG 编辑器

## 6. 验收场景

- 当前模型不支持 tools，用户输入搜索任务：显示建议但不自动切换；点击后才切换。
- 工具模型执行搜索任务：助手消息显示工具时间线。
- 用户打开模板选择器：可选择内置工作流，填写变量后进入输入框；当前模型不变。
