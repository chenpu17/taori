## 1. 一句话定位

**Taori = 面向中文 BYOK 用户的多模型工作台。**

更展开一点：

> 如果你已经同时在用 DeepSeek、火山方舟、硅基流动、华为 MaaS、OpenRouter 或 Ollama，Taori 想做的不是再包一层聊天壳，而是把 **失败兜底、成本透明、多模型决策** 三件事做成默认体验。

## 2. 30 秒介绍版本

> 我最近在做一个桌面 AI 助手 **Taori**。  
> 它不是“再来一个 ChatGPT 壳子”，而是给 **多模型 BYOK 重度用户** 用的：  
> 1. 模型挂了/慢了/不合适时，能继续干  
> 2. 每次调用花多少钱能看见  
> 3. 重要问题能让多个模型一起给结论  
>   
> 现在已经有 browser-first 版本可跑，国内 provider 直连、多模型对比、圆桌、成本面板、模板市场这些主链路都能体验。

## 3. 发布时要反复强调的 4 个点

1. **不是大而全 hub**
   - 不跟 Cherry Studio / LobeChat 拼“插件最多、生态最大”
   - 重点是中文 BYOK、多模型连续工作流

2. **国内 provider 一等公民**
   - DeepSeek / 火山方舟 / 华为 MaaS / 硅基流动 / PackyAPI / Ollama
   - 不只是“填个 OpenAI 兼容 base_url”

3. **成本透明是主轴，不是附属功能**
   - 调用前预估
   - 调用中实时
   - 调用后聚合
   - 预算阈值可见

4. **多模型不是摆着看，而是拿来做决策**
   - Quick Compare
   - 圆桌
   - Workflow Recipe
   - 模板市场

## 4. 各社区建议发法

### 4.1 少数派（偏产品故事 + 工作流）

标题方向：

- `我做了一个给中文 BYOK 重度用户用的多模型 AI 工作台`
- `当你已经同时在用 DeepSeek / OpenRouter / Ollama，为什么还需要 Taori`

建议结构：

1. 先讲痛点：多模型用户每天真实遇到什么问题
   - 模型切来切去
   - 成本心里没底
   - 关键问题需要多模型交叉判断
2. 再讲为什么不是“再做一个 AI 壳子”
3. 展示 Taori 三主线
4. 放 2–3 个真实使用场景
   - 选模型
   - 看成本
   - 做决策
5. 最后给 GitHub / README / 试用方式

## 5. 可以直接复用的“当前可用功能”列表

- 多轮聊天、模型切换、停止与续写
- Provider / Model 管理（Model Center）
- 成本看板、预算与实时成本
- Quick Compare（多模型并行对比）
- 圆桌（多模型结构化讨论）
- Prompt 模板、Persona、Workflow Recipe、模板市场
- MCP 管理、工具健康、Run Timeline

## 6. 发布时不要讲成什么

- 不要说成“最强 AI 客户端”
- 不要说成“比 Cherry Studio / LobeChat 全面”
- 不要说成“插件生态平台”

更合适的说法：

- **面向中文 BYOK 用户**
- **强调多模型连续工作流**
- **强调成本透明 + 失败兜底 + 决策支持**
