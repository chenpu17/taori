# 26 · P6 深度研究

Status: proposal  
Owner: Taori  
Date: 2026-05-11

## 1. 产品目标

深度研究不是“会搜索的普通聊天”，而是一条可持续推进、可中断恢复、可核查证据的高频工作流。

目标体验：

- 用户给出一个主题或问题后，Taori 先产出研究计划，再分阶段检索、阅读、整理证据，最后输出带引用的结论。
- 用户在过程中能随时看到“系统正在做什么、已经花了多少、当前证据够不够、下一步准备做什么”。
- 研究结果不是一次性对话文本，而是一份可继续补充、导出、回看来源的本地研究稿。

## 2. 典型用户故事

- 作为重度 AI 用户，我要调研一个新领域，希望系统先拆解问题，再逐步搜集材料，而不是直接给一段泛泛答案。
- 作为产品/投资/咨询用户，我希望结论后面带来源，能区分“事实”“推断”“建议”。
- 作为工程用户，我可能中途暂停，之后回来继续，不想从头再做一遍检索。
- 作为成本敏感用户，我希望研究任务能设预算和轮次，不让联网检索无限膨胀。

## 3. 与现有能力的关系

| 能力 | 定位 | 是否适合替代深度研究 |
|---|---|---|
| 普通聊天 | 单回合或短多轮问答 | 否，缺少计划、阶段状态和证据归档 |
| Workflow Recipe | 可复用的启动配方 | 否，可作为深度研究的启动模板，但不负责执行状态机 |
| Roundtable | 多模型并行辩论/发散 | 部分适合，可用于研究中的“观点对照”，但不应承担主编排 |
| 轻量 RAG / 文件检索 | 研究素材输入层 | 是深度研究的底座之一，但不等于完整研究工作流 |

## 4. 目标体验

### 4.1 启动

用户从聊天页或模板市场进入“深度研究”，输入：

- 研究主题
- 目标产出（摘要 / 报告 / 对比表 / 决策建议）
- 预算偏好（快 / 平衡 / 深入）
- 可选范围约束（时间区间、地域、语言、必须引用数量）

系统先不直接开跑，而是生成一份**研究计划预览**：

1. 研究问题拆分
2. 预计阶段
3. 预计使用的工具
4. 预算与中断点

用户确认后才开始执行。

### 4.2 执行阶段

统一采用 6 阶段：

1. **选题澄清**：把用户问题重写成可执行研究任务
2. **研究计划**：列关键子问题、检索策略、停止条件
3. **检索抓取**：搜索网页、抓取候选来源、去重与初筛
4. **证据整理**：提取事实、标记来源、聚合冲突点
5. **草稿生成**：输出带“事实 / 推断 / 建议”分层的初稿
6. **引用校验**：检查引用可回溯、结论是否有足够证据支撑

用户在 UI 中应持续看到：

- 当前阶段
- 已完成子任务数
- 已纳入的来源数
- 已花费成本 / 剩余预算
- 最新草稿快照

### 4.3 中断与恢复

- 用户可手动暂停。
- 成本超出软预算时自动停在安全检查点，等待用户确认继续。
- 切换页面、刷新或重启后，能从最近一个阶段继续，而不是重新检索全部来源。

### 4.4 最终产物

深度研究输出不只是聊天消息，还应至少包含：

- 最终摘要
- 结构化章节
- 引用来源列表
- 关键事实卡片
- 未解决问题 / 风险

## 5. MVP 范围

### 必须支持

1. 单主题研究任务创建与恢复
2. 研究计划预览与用户确认
3. 网页搜索 + 网页抓取 + 本地文件检索三类素材来源
4. 带引用的 Markdown 结果
5. 预算与阶段状态可视化
6. 手动暂停 / 继续

### 延后支持

- 多任务队列与后台批处理
- 自动生成幻灯片 / 图表
- 云端协作与多人批注
- 自动安装第三方 MCP 数据源
- 无人值守长时自治研究

## 6. 体验原则

- **先计划，后执行**：不直接开始大规模检索。
- **证据先于结论**：结论必须能追溯到来源。
- **事实与推断分层**：避免把模型脑补和原始证据混在一起。
- **过程可见**：用户能看到研究到底卡在哪一步。
- **可恢复**：阶段状态和中间产物必须持久化。

## 7. 验收标准

- 用户能创建一个深度研究任务，并在确认计划后启动。
- 执行中能看到阶段、来源、成本与中间草稿。
- 中断后能恢复到最近阶段。
- 最终结果至少包含摘要、正文、引用与风险/待确认项。
- 任一引用都能回到对应来源记录，而不是只剩裸文本。
