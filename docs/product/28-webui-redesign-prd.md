# 28 · Taori WebUI 重设计 PRD（设计师交付版）

> 目标读者：网页 UI 设计师 / Claude Design。
> 本文目的：为 Taori WebUI 的一次"心智模型层"重设计提供完整、自洽的需求；设计师可基于此直接产出高保真稿，无需读其他文档。
> 范围：浏览器端 WebUI（桌面 ≥1280 / 平板 768–1279 / 手机 <768）。Desktop 壳为 follow-up，不在本轮范围内。

---

## 1. 背景与一句话目标

**产品：Taori — 多模型桌面 AI 助手（BYOK，自带 API Key）。**

> *Taori weaves many models into one continuous flow.*
> 把多个模型，织成一条不断的工作流。

现有 WebUI 经过多版本迭代后存在严重的"功能并列堆叠"问题：聊天、深度研究、圆桌、快速对比、模型中心、成本看板、控制中心等被实现为彼此独立的 surface，与产品叙事中的"一条对话"严重错位。

**本轮重设计的一句话目标：**

> 让用户打开 Taori 后只看到一件事 —— 一个对话框；所有"模型能力"都在这条对话里发生，配置只在需要时浮出。

---

## 2. 目标用户与使用场景

| 维度 | 描述 |
|---|---|
| 用户画像 | 已经在同时使用 ≥2 个 AI 模型（ChatGPT / Claude / 本地模型 / OpenRouter 等），愿意自带 API Key，对成本和稳定性敏感 |
| 技术水平 | 中高级，对"模型"、"Provider"、"Key"等概念熟悉 |
| 首要痛点 | 多模型切换成本高、不知道花了多少钱、模型挂了之后手忙脚乱 |
| 典型场景 | ① 普通聊天 ② 用 3 个模型讨论一个问题 ③ 跑一次深度研究 ④ 让 Sonnet 写、GPT-4o 改 |

---

## 3. 产品三主线（驱动设计决策）

这三条主线在每一个界面元素里都必须找得到对应：

1. **失败兜底** — 模型挂了/慢了/限流了，自动换路继续，**且让用户看见这次切换**。
2. **成本透明** — 调用前预估、调用中实时、调用后聚合；BYOK 用户的"安全感"。
3. **多模型圆桌** — 重要决策时让多个模型并行回答，形成共识/分歧/决策。

---

## 4. 核心心智模型（最重要的一节）

> **"你跟 Taori 说话。Taori 背后是一支模型团队 —— 你随时可以让它换人、开会、深入调研，但永远只在这一条对话里。"**

界面层的直接推论：

1. **只存在一个工作 surface：对话。** 圆桌、研究、对比、生图 **不是** 独立页面，而是这条对话里的"动作（action）"或"回合类型（turn type）"。
2. **模型身份"低声播报"** — 用户看得到，但不抢视线。
3. **配置不是目的地** — 模型/工具/预算设置只在主动找或出问题时浮出。
4. **成本/健康是 ambient（环境）信息** — 一行底栏常驻，点开才有看板。

---

## 5. 设计原则

| # | 原则 | 落地表现 |
|---|---|---|
| P1 | **只有一条对话** | 没有 Research/Roundtable/Compare 等独立 surface；所有 AI 行为内嵌在对话流 |
| P2 | **默认不打扰** | 模型名、用时、成本都是 11px 灰字；只在 hover/点击才出详情 |
| P3 | **高级动作有低门槛入口** | `+` 按钮（鼠标）与 `/` 命令（键盘）露出同一份模式菜单 |
| P4 | **配置不是目的地** | 整个 app 只有一个配置入口（Header 右上 `⋯`），里面只有 2 个二级页面 |
| P5 | **失败必须可见** | 模型自动切换时永远 inline 提示一次，且永远可撤销 |
| P6 | **首次零配置即可开聊** | 没 Key 也能进主界面；只有按"发送"时才抬出最小配置卡 |

## 6. 信息架构（IA）

整个 app 从顶到底只有 **三区 + 一菜单**：

```
┌─────────────────────────────────────────────────────┐
│ Header（极薄）                              ⋯        │
├──────────┬──────────────────────────────────────────┤
│          │                                          │
│ Sidebar  │   Main（唯一工作区：对话）              │
│          │                                          │
│          │   ┌────────────────────────────────┐    │
│          │   │  Composer（输入框）            │    │
│          │   └────────────────────────────────┘    │
├──────────┴──────────────────────────────────────────┤
│ Footer（一行环境信息）                              │
└─────────────────────────────────────────────────────┘
                                                ▲
                                Header 右上 `⋯` 是
                                唯一的配置入口浮层
```

被砍掉的页面/surface（设计稿不应再出现）：

- ❌ ControlCenter 独立全屏页（7 段）
- ❌ CostDashboard 独立页
- ❌ ResearchCenter 独立 surface
- ❌ Roundtable / RoundtablePanel 独立 surface
- ❌ ModelCenter 独立全屏
- ❌ 多步骤 Onboarding 流程
- ❌ Sidebar footer 区的用户头像、主题切换、设置按钮（合并到 ⋯）
- ❌ Header 右上的 4 个独立功能图标（成本/模型/帮助/设置 → 合成 1 个 `⋯`）

### 7.4 Composer（输入框）

这是整个 app 最关键的组件，单独详述。

```
┌──────────────────────────────────────────────────────────────┐
│  ＋   说点什么……  按 / 调用模式            Sonnet ▾    ↑    │
└──────────────────────────────────────────────────────────────┘
   │                                            │           │
   左：模式按钮                  右下：模型选择器      发送
   ↓                              ↓
   点击 = 弹出模式菜单            点击 = 弹出模型清单
   `/` 键 = 弹出同一份菜单        显示当前默认模型简称
```

**模式菜单（`+` 与 `/` 共用）**：

```
┌──────────────────────────────────────┐
│ ⊕  圆桌      让 3 个模型一起讨论     │  /roundtable
│ 🔎 研究      多轮搜索 + 综述         │  /research
│ ⇆  对比      并排看 2-3 个模型回答   │  /compare
│ 🎨 生图      调用图像模型            │  /image
│ 📎 附件      也可以直接拖文件        │  /file
└──────────────────────────────────────┘
```

**模型选择器（右下小下拉）**：

- 默认显示当前 active 模型的简称（如 `Sonnet ▾` 或 `GPT-4o ▾`）
- 点击展开**最近 5 个 + 搜索框 + "管理所有模型 →"**
- 不在这里暴露 provider、价格、能力 —— 这些去"管理"页面

**附件状态**：拖入文件时 Composer 上方出现 chip 区，显示文件名 + 缩略图 + ✕。

### 7.5 Assistant 消息（模型身份"低声")

```
Taori
这是回答的正文……可以是长文本、Markdown、代码块、表格。
多行内容继续……

· Sonnet 4 · 1.2s · ¥0.04 · ↺ 换个模型重答     ← 11px 灰字
                                                ↺ 仅 hover 时浮现
```

设计要点：

- **不显示 AI 头像**（避免拟人化和视觉噪音）
- "Taori" 作为发件人标识，单行小标题
- 消息底部 **一行 11px 灰字**：`模型简称 · 用时 · 成本`，hover 出 tooltip 展开 token 数、provider
- "↺ 换个模型重答" 仅 hover 出现，鼓励"换一根线继续织"（呼应 Slogan）
- 代码块、Markdown、表格沿用现有 markdown 渲染规范

### 7.6 用户消息

```
我
帮我把这段翻译成英文……
```

- 极简：发件人小标识 + 内容；没有时间戳、没有头像、没有 action 按钮（hover 时可出"编辑/重发"）

### 7.8 失败兜底 inline 提示（信任关键点）

```
Taori
回答正文……
· GPT-4o · 0.9s · ¥0.03

⚠ Sonnet 限流，已自动切到 GPT-4o。  [撤销] · [不再自动切换]
```

- 浅黄底 + 细线左侧条；高度约 32px，**不打断**阅读
- "撤销"：把这条消息删掉并用原模型重试
- "不再自动切换"：写入设置，未来限流时改为 inline 询问

### 7.9 Footer · 环境状态条

```
●  在线      今日 ¥0.42      本会话 ¥0.04
```

- 高度 32px，全局常驻
- `●` 颜色：绿 = 正常 / 黄 = 部分降级 / 红 = 不可用
- 点击 `●` → 浮起 mini 健康面板（哪个 provider 慢/限流，最近 24h 错误率）
- 点击 `今日 ¥0.42` → 浮起 mini 成本看板（今天/本周/本月，按模型分桶，最近 5 笔调用）
- 点击 `本会话 ¥0.04` → 浮起本会话所有调用的明细列表

**这三个 popup 取代了原本的 CostDashboard 整个页面。**

### 7.10 首次无 Key 状态

主界面**不变**：依然是空对话框 + Sidebar + Footer。区别只有：

- Footer 左侧状态点显示 `● 未配置`
- 输入框 placeholder：`先配一个 API Key 才能聊 —— 点这里`
- 用户尝试发送时，**抬出一张 inline 配置卡**（不跳页面、不全屏遮罩）：

```
╭─ 先配一个 Key ──────────────────────────────────╮
│  推荐 OpenRouter（一个 Key 接入所有模型）      │
│                                                 │
│  ○ OpenRouter   ○ OpenAI   ○ Anthropic         │
│                                                 │
│  ┌─────────────────────────────────────────┐    │
│  │ sk-or-……                                │    │
│  └─────────────────────────────────────────┘    │
│                                                 │
│  [跳过浏览]                  [测试并保存]       │
╰──────────────────────────────────────────────────╯
```

- 测试通过后：① 关闭卡片 ② 自动写入第一个默认聊天模型 ③ 把用户原本要发的内容**填回输入框**，等他按发送

**Onboarding = 一张卡，不是一个流程。**

### 7.12 二级页面 A · 模型 & 工具

这是一个**右侧抽屉**（drawer），从右侧滑入，宽度约 720px，**不全屏遮罩**（让用户随时回到对话）。

左侧三个 tab，右侧详情区：

```
┌───────────────────────────────────────────────────────┐
│  模型 & 工具                                     ✕    │
├──────────┬────────────────────────────────────────────┤
│ Providers │  [Provider 列表 + 添加按钮]                │
│ 模型      │                                            │
│ 工具      │                                            │
│ 模板      │                                            │
└──────────┴────────────────────────────────────────────┘
```

各 tab 内容：

- **Providers**：列表（已连接 / 未连接），添加按钮（弹同一张配置卡）
- **模型**：按 capability 分组（聊天 / 图像 / 嵌入），每行显示 `名称 · provider · 价位徽章（💰/💰💰/💰💰💰）· 默认标记 · 启用开关`；可拖拽排序设定备援顺序
- **工具**：内置工具开关（file_search、web_search 等）+ MCP 接入
- **模板**：Prompt 模板、Persona 预设（列表 + 新建）

## 9. 交互细节

| 行为 | 触发 | 反馈 |
|---|---|---|
| 调起模式菜单 | 点 `+` 或敲 `/` | 浮层从 Composer 上方升起 |
| 选择模式 | 点击模式项 或 `/research` 后按 Enter | Composer 出现一个模式 chip：`🔎 研究：` |
| 取消模式 | 点 chip 上的 ✕ | 回退到普通聊天 |
| 切换模型 | 点 Composer 右下下拉 | 不重发，只改下次回合的目标模型 |

| 撤销自动切换 | 点 inline 提示的"撤销" | 删除那条回答 + 用原模型重试 + 该会话内禁用自动切换 |
| 看费用细节 | 点 Footer `今日 ¥0.42` | 浮层 mini 看板 |

## 10. 视觉方向

> **不强制**，设计师可自由提案；以下是当前项目已建立的方向作为参考起点。

| 维度 | 当前方向（可保留可改） |
|---|---|
| 色调 | 暖纸黑墨（warm paper / ink），主色 `#F4EFE4` 纸面，主文 `#1A1612` |
| 强调色 | 朱红（`#9B3D2F` "thread"）+ 山青（`#2C5F5D`）+ 金（`#B8893A`） |
| 字体 | 中文衬线（Noto Serif SC）用于标题 / 品牌；正文 Geist / Inter 无衬线 |
| 阴影 | 极克制，仅用 1–8px 软阴影 |
| 圆角 | 6–14px，对话气泡偏 14 |
| 留白 | 充分（参考"和纸"质感） |
| 动效 | 160ms / 280ms 缓动；不要弹跳，倾向 `cubic-bezier(0.22, 1, 0.36, 1)` |

如果设计师认为暖纸调对 BYOK 技术用户不够"工具感"，**可以提案改成更冷的版本**，但请保留"低对比、低饱和、不打扰"的整体气质。

## 14. 验收标准（用户可感的衡量点）

完成的设计应能让一位**全新用户**：

- [ ] 打开网页后 **2 秒内** 知道"这是个聊天工具，我应该往哪打字"
- [ ] 在不读任何文档的情况下，找到"开圆桌" / "做研究" / "切模型"的入口（≤ 2 次点击或 1 个 `/`）
- [ ] 永远看得到当前对话花了多少钱（不需要切页面）
- [ ] 当模型被自动切换时，立刻明白"发生了什么 + 怎么撤销"
- [ ] 配置 API Key 的整个过程 **≤ 3 步**

## 附录 B · 关键术语

| 术语 | 含义 |
|---|---|
| 对话 | 一条用户与 Taori 的多轮交流 |
| 回合（turn） | 对话中的一次"提问 + 回答"；可以是普通、圆桌、研究、对比、生图 |
| 模式（mode） | 用户用 `+` / `/` 主动选择的回合类型 |
| 模型 | 一个具体的 LLM/图像/嵌入模型实例（如 Sonnet 4） |
| Provider | API 服务提供方（OpenRouter / OpenAI / Anthropic / Custom） |
| 兜底（fallback） | 模型挂了之后自动换另一个模型继续 |
| BYOK | Bring Your Own Key，用户自带 API Key |
